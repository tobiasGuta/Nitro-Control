# Manual qualification on Acer Nitro AN515-58 and Fedora

The [preview.5 qualification results](HARDWARE-QUALIFICATION-RESULTS.md) record the reference run, its deferred checks, and the Conditional GO. Use this checklist for subsequent runs and record results against the exact candidate source and binaries. Earlier owner observations are archived in the [native RGB guide](NATIVE-RGB.md) and the [RGB incident record](RGB-INCIDENT-2026-11.md).

## Session record and common prerequisites

Record the source revision or archive digest, installed application and helper versions, module digest and `vermagic`, Fedora and kernel versions, BIOS/EC versions if reported, GPU driver version, Secure Boot and lockdown state, desktop session type, AppIndicator extension version, and AC or battery power. Use the reference four-zone AN515-58, stock `acer_wmi`, a local GNOME login with a working authorization agent, and a supported kernel build. Keep a local console and an approved stock recovery path available. Disable competing monitoring and control tools for the baseline. Record any service or helper deliberately left active.

Start on AC, at idle, with firmware fan control verified in Auto. Let the system settle before recording reference temperatures and fan speeds. Check one write at a time. Pause between stages for stable sensor readings and inspect the journal after driver, module, or suspend events. Skip hardware-write stages if the platform, helper, module, authorization, or baseline does not qualify. An operator must explicitly confirm every physical change. Preserve raw observations, expected result, actual result, and a Pass, Fail, or Deferred result for every row.

Use the existing [fan safety and recovery guide](FAN-CONTROL.md) and [native RGB installation and recovery guide](NATIVE-RGB.md) for authorized manual operations. Keep Secure Boot and firmware settings as found. If policy rejects the module, record the refusal and defer native writes until a compatible, approved configuration is available.

A manual fan override can survive GUI closure. Keep this stage supervised and complete Restore Auto before ending it. A GUI or client timeout does not establish that an authorized operation has stopped.
